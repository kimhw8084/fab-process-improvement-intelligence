# Business value and operator testing — no synthetic ROI promises

For each product, pre-register 3–8 representative tasks with eligible engineers and document current tools, baseline completion rates and wall-clock time. Evaluate assisted work on comparable cases, including result review, corrections, failed investigations, source questions and extra steps.

`net_annual_hours = eligible_users × annual_tasks_per_user × (accepted_manual_time - accepted_assisted_time) - support/maintenance/rework_hours`. Do not convert hours to cash without finance-approved economic assumptions and demonstrated actual realization. `ROI_cash = (finance_recognized_benefits - fully_loaded_TCO) / fully_loaded_TCO` when TCO > 0. Noncash engineering capacity value is a distinct reported benefit.

Collect: case selection criteria, reviewer agreement, valid task success, abstention reasons, useful-finding acceptance, net engineer minutes, adoption per eligible task (not logins), and cross-team replication effort. Do not train or tune using held-out user evaluation cases. Record confidence intervals for observed time reductions and failure rates where sample sizes support them. At least two FAB team types should be represented before claiming generalized applicability; otherwise label narrower scope.

Test workflow accessibility/UX: source selection clarity, comparison choice, data coverage, uncertainty interpretation, false-cause handling, reproducible export, cancel/restart, keyboard interaction, and error recovery. 'Zero clicks' must not hide meaningful choices or human approval boundaries.
