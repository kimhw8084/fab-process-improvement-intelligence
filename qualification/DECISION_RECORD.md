# P4 implementation decision record

Date: 2026-11-22 (client timezone). Product scope: P4 only; shared contract remains frozen at v1.0.0.

## Implementation choices

1. **Keep the product runtime standard-library-only.** Product analysis, CLI, local UI, and MCP client use the Python standard library; the browser page has no package tree, CDN, remote fonts, telemetry, or updater. Qualification-only packages are pinned separately and are not product runtime dependencies.
2. **D01 uses estimable regression models and withholds weak inference.** Pivoted QR identifies rank/alias problems. The fitter supports linear/quadratic/two-factor terms, categorical fixed effects and declared factor-by-category slopes, HC3 or independent-cluster sandwich covariance, and coefficient/influence diagnostics. Small cluster counts, degenerate residual variation, unsupported prediction, and unidentifiable terms do not receive invented confidence intervals. It does not automatically add random effects: the UI/model contract makes no distributional or mixed-effects assumptions for an unknown fab population. When an independent unit is declared, an explicitly selected cluster grouping must contain each such unit wholly; otherwise uncertainty is withheld. In an independent 2,000-trial paired-lot null challenge, statsmodels' cluster sandwich falsely rejected 15.4% of cases when repeated lots were split across chamber clusters (Wilson95 13.9–17.0%), compared with 4.8% when correctly clustered by lot (3.9–5.8%). A P4 coarser chamber grouping remains valid when every lot maps to one chamber cluster. A separate 1,200-trial chamber×product challenge found a 33.5% null false-positive rate (Wilson95 30.9–36.2%) for one-way lot clustering and 4.67% (3.61–6.01%) for Statsmodels' two-way reference; P4 now accepts `shared_dependence_fields`, reports crossed group membership, retains point estimates, and withholds intervals when a declared group crosses independent units. A new 250-trial fixed-design known-effect challenge showed that near-collinear but full-rank factors can yield almost random coefficient signs and very wide marginal intervals. D01 now surfaces elevated/severe warnings using a squared pivoted-QR diagonal-ratio heuristic; it leaves the intervals visible, states that thresholds are descriptive rather than universal identifiability tests, and never selects a different formula. Statsmodels is not promoted to runtime because its crossed covariance implementation covers exactly two dimensions and adds a large NumPy/SciPy/Pandas/Patsy/formulaic closure; three-way and undeclared dependence still require a qualified method or abstention. These generated-method checks do not estimate a process-population error rate.
3. **D02 treats model-supported space as exploration.** It fixes omitted controllable factors at explicit settings, requires matching cluster-robust covariance when rows repeat independent units, rejects null, blank, and composite independent-unit IDs; splits whole independent units before fitting, and classifies each grid cell as observed/interpolated/extrapolated/unsupported/forbidden. Local group-maximum absolute errors produce a pointwise empirical diagnostic only with enough nearby holdout groups; they do not provide a coverage guarantee after searched-grid selection. The earlier maximum-score band inferred its target panel from calibration rows without requiring a precommit record, so that interface did not rule out adaptive panel selection. The corrected band now requires caller-supplied references for the model-selection plan and thresholds, an exact constrained-metric family, a complete exact-setting panel, and a precommitted observation count at each setting (one under the legacy single-row default). The implementation checks that every independent calibration unit matches both the exact setting panel and row count; a replicate mismatch withholds the finite-panel band. Normalized plan bytes receive a SHA-256 identity. References and timing remain unauthenticated by P4, so the band is still assumption-conditional and interpolation remains uncovered. An independent 5,000-trial equal-error challenge measured 95.3% coverage for a fixed one-setting band, 86.3% when selecting the smallest apparent radius among 25 settings, and 95.42% for a predeclared complete-panel max score. The separate 1,000-trial nonlinear, correlated two-metric challenge observed 966/1,000 joint panel coverage (Wilson 95% interval 0.953–0.976) and 0/1,000 post-selection false-feasible units, with 3.06 mean candidate cells. These are generator-specific checks, not process-population or interpolation evidence. A separate 5,000-trial iid-normal row-count-shift oracle measured 94.56% matched-panel coverage (Wilson95 [0.939, 0.952]), 89.78% at two future observations per setting, and 81.94% at four. A new paired 250-trial challenge holds tool/time composition and all nine exact settings constant while shifting the held-out chamber response: average trial-level exact-panel misses were 4.92% at zero shift, 25.73% at shift amplitude 0.025, 88.22% at 0.05, and 100% at 0.10 and 0.19. At the strongest shift, outcome counterevidence appeared in all trials and the paired miss fraction increased in all trials. This verifies descriptive response-drift counterevidence for this generator; it is not a transfer test, conditional coverage claim, or future-population estimate. D02 now requires the declared calibration row count at every panel setting, rejects invalid independent-unit IDs, and reports held-out panel-count and outcome misses without changing selected candidates; it cannot verify future sampling structure. Extrapolated, sparse, insufficiently calibrated, and forbidden cells are never candidates; no grid is represented as a qualified production recipe.
4. **D03 has two explicitly scoped family-wise mean envelopes.** The default Cornish-Fisher t rectangle passed an independent SciPy `t.ppf` critical-value oracle on its supported domain and had 95.8%/96.8% joint coverage in 500 correlated normal/t(5) trials. However, a separate independent challenge revealed skew sensitivity: at 30 lots, joint coverage was 91.8% (Wilson95 [0.891, 0.939]) for bounded, skewed Beta responses. We added an optional distribution-free Hoeffding/Bonferroni rectangle that requires the caller to state an exact candidate-setting ID family, matching metric units, hard bounds for independent-unit aggregates, and source/precommit references. P4 checks ID/unit equality and observed values inside the supplied bounds, but cannot authenticate the support or references; invalid contracts abstain without falling back to t intervals. In 500 trials with four correlated equal-mean settings, the bounded envelope had 100% joint coverage at 30 and 60 units (Wilson95 lower 0.992), with 3.0–3.6× the t-interval width. These finite synthetic results do not establish general coverage. No exclusions are allowed for family-wise output; means remain descriptive, the relationship contract remains synthetic, and no causal claim or company authority is inferred.
5. **D04 retains justified standard designs plus guarded sequential search.** The non-executing planner supports randomized full factorial, resolution-IV half fraction, face-centered central-composite response-surface, basic Latin hypercube, and finite-grid greedy D-optimal designs. The seeded comparison found P4's D-optimal search matches exhaustive optimum and pyDOE3 on the fixed benchmark, while SciPy random-coordinate LHS improves centered discrepancy over basic LHS; the portable basic design remains and no optimization code is copied. P4's response-surface design exactly matches pyDOE3 CCF geometry and has full quadratic rank at 2–5 factors; a noiseless known 3-factor quadratic was recovered over a 125-point held-out grid to max absolute error 3.8e-15, while the 8-run full factorial is rank 7/10. PyDOE3's official BSD-3 implementation is qualification-only; upstream marks pyDOE3 archived and points to the consolidated PyDOE project, so no runtime dependency was added for this bounded face-centered generator. Sequential expected-improvement proposals are offered only after independent-unit grouped holdout validation meets the engineer-specified error cap; multimodal benchmark cases fail closed. The D02 confirmation path requires a supplied reference, approved bounds, source-backed paired-SD/MDE, power inputs and run budget, then returns randomized complete pairs for engineer review. Its original normal sample-size formula underpowered all 54 fixed scenarios against SciPy's noncentral-t oracle (minimum achieved power 0.121). The product now uses a three-term Cornish-Fisher t-critical approximation, normal power-tail approximation and one extra pair; it was not underpowered in those 54 cases and exceeded exact minimum by a mean 1.83 pairs (maximum 8). This finite oracle grid is not an exact or universal power guarantee; no experiment is executed.
6. **D05 separates numerical DiD diagnostics from interpretation eligibility.** Randomized studies use assigned units for ITT, distinguish assigned from observed outcomes, and report attrition and Welch-t intervals. DiD retains descriptive point/interval estimates, unit-checks its sensitivity bounds, reports exact null tipping points, and exposes its numerical gate state. A 1,000-trial known-confounder benchmark found raw Welch intervals covered the true effect in 5/1,000 cases; intervals expanded by the oracle-adequate injected bias bound covered 973/1,000, while a bound fixed at one-quarter of hidden bias covered 40/1,000. Numerical gates passed with a wrong true-effect direction in 626/1,000 underbound cases. Therefore P4 never emits an observational DiD `causal_claim`; conditional interpretation remains pending independent substantive qualification of the bound source. This is a synthetic known-generator stress test, not company evidence.
7. **The MCP adapter is configurable but site-owned.** The official Python SDK transports and explicit tool/result maps implement logical contract 1.1.0. A complete synthetic bounded-read-to-P4 workflow validates source semantic/version receipts, source hashes, approved relationship, joined keys/grain/time scope and audit data before creating the standard evidence envelope. No real tool identifiers, source semantics, joins, permissions, host, or credentials are supplied. Company configurations remain `PENDING_INTERNAL`; the site-side runner requires local approval references and an explicit configuration.
8. **P4 contributes a headless panel to the P1-owned workspace.** P4 ships no competing shell, route system, or design tokens. Its React/TypeScript panel consumes the shared source preview and evidence envelope, delegates charts to the host, and preserves D02/D03 uncertainty, D04 paired-arm plans, and D05 pending-bound qualification in semantic tables. Twelve component tests and strict type-checking pass against the local P1 package and schema snapshot. The accessible P1 host also passed its own 38 UI tests, strict typecheck, build, and 11 host-route tests; an isolated copy using the current P4 source passed its 12 panel tests, strict typecheck/build and real browser flow with all five sections and filtering. P1 has no Git metadata and the host registry still pins an older P4 snapshot, so this is demonstrated compatibility but not upstream or suite release qualification. Formal WCAG, screen-reader and target-OS review remain pending. The retired standalone page stays in local legacy evidence and is excluded from the transfer bundle.

## Qualification and OSS decisions

- **D03 preserves opaque unit identity and fails closed on missing rows.** A deterministic two-objective independent oracle found that `str(unit_id)` merged integer `1` with string `"1"`; this changed the correctly nondominated two-setting mean front into a single-setting front. D03 now keys IDs by both type and value and withholds the comparison if a required observed-unit ID is missing or invalid. This is an input-integrity correction, independent of the Bonferroni uncertainty envelope; the mean front remains descriptive.
- **D04 requires an uncertainty-aware SD design input.** A 2,000-trial normal-theory historical-SD challenge using SciPy's chi-square and noncentral-t oracles found that plans using the sample SD as known were underpowered in 41.1–55.8% of trials across historical df 5/10/30/100. Plans sized from a one-sided 95% chi-square SD upper bound were underpowered in 3.0–5.15% (with large run-count costs for small df). The confirmation API now refuses a point estimate and requires a caller-supplied ≥95% one-sided upper bound with df, or an engineer-approved hard bound. The planner records the basis but does not compute/authenticate it; the method still assumes a valid source, normal paired differences, independent randomized blocks, and a future comparison consistent with the bound.
- **D05 validates assigned-unit identity and attrition bounds.** Randomized and DiD observations now require nonempty string unit IDs that match the string assignment ledger exactly; numeric/string coercion cannot turn mismatched units into an assigned causal study. Randomized worst-case ITT bounds are refused if any observed response lies outside the supplied outcome range. The independent arithmetic oracle for one missing treatment response under `[0,20]` yields treatment mean `[9.25,14.25]`, control `[9,9]`, and effect bounds `[0.25,5.25]`; this remains conditional on caller-supplied valid bounds, not a point estimate.

- Product runtime has no third-party Python packages. `qualification/benchmark-requirements.txt` pins NumPy, SciPy, scikit-learn, pyDOE3, scikit-optimize, and statsmodels for independent references and the D04 tournament. A clean environment on the recorded build host ran the full test suite with zero skipped tests. The entire resolved optional tree was scanned with pip-audit; this does not replace source review, OS/interpreter scanning, or a license/ownership decision.
- Workspace continuation ledgers remain in `progress/` beside the source but are excluded from the product transfer ZIP; they are development-state records, not engineer-facing runtime material. A bundle inventory regression test preserves the distinction.
- The previous scikit-learn 1.2.2 pin matched CVE-2024-5206; it was raised to 1.5.2 and the resulting current package advisory scan found no known vulnerabilities. See `release/DEPENDENCY_AUDIT.json` for full resolved versions and scanner scope.
- The fixed D04 benchmark compares SciPy `qmc.LatinHypercube` (basic/random-CD), pyDOE3 D-optimal against exhaustive enumeration, and scikit-optimize GP expected improvement using identical seeded functions and stated metrics. Keep results and limits in `release/D04_OSS_COMPARISON.json`; the runtime does not import these alternatives.
- No heavier causal, Gaussian-process, or multiobjective package was added to the product. The tested product capabilities and explicit refusal boundaries do not show a need for those dependencies in runtime. This does not claim that the bounded implementation replaces those packages for broader designs.
- Reviewed the MIT-licensed R package HonestDiD. Its event-study inference requires an event-time coefficient vector and covariance matrix; P4's present single pre/post contrast does not supply those objects, so using its method here would be unsupported. Its R/CVXR solver closure also adds offline runtime dependencies without extending this estimand. No product dependency was added; future multi-period event-study scope should evaluate it directly.
