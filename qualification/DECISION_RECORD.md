# P4 implementation decision record

Date: 2026-11-22 (client timezone). Product scope: P4 only; shared contract remains frozen at v1.0.0.

## Implementation choices

1. **Keep the product runtime standard-library-only.** Product analysis, CLI, local UI, and MCP client use the Python standard library; the browser page has no package tree, CDN, remote fonts, telemetry, or updater. Qualification-only packages are pinned separately and are not product runtime dependencies.
2. **D01 uses estimable regression models and withholds weak inference.** Pivoted QR identifies rank/alias problems. The fitter supports linear/quadratic/two-factor terms, categorical fixed effects and declared factor-by-category slopes, HC3 or independent-cluster sandwich covariance, and coefficient/influence diagnostics. Small cluster counts, degenerate residual variation, unsupported prediction, and unidentifiable terms do not receive invented confidence intervals. It does not automatically add random effects: the UI/model contract makes no distributional or mixed-effects assumptions for an unknown fab population.
3. **D02 treats model-supported space as exploration.** It fixes omitted controllable factors at explicit settings, requires matching cluster-robust covariance when rows repeat independent units, splits whole independent units before fitting, and classifies each grid cell as observed/interpolated/extrapolated/unsupported/forbidden. Local group-maximum absolute errors produce an empirical interval only with enough nearby holdout groups. A finite 95% order-statistic rank is used, but distance-based local selection does not provide a distribution-free conditional-coverage guarantee; the split reference is supplied provenance and is not independently authenticated. Convex-hull membership alone is not evidence. Extrapolated, sparse, insufficiently calibrated, and forbidden cells are never candidates; no grid is represented as a qualified production recipe.
4. **D03 requires an explicit approved relationship contract.** Upstream and downstream evidence must name source/version, key, grain, population, metric, event times, factor keys, lag, and approval reference. The implementation checks row lineage, one-to-one pair keys, compatible populations, temporal order, independent units, per-setting minimums, both objective directions, and uncertainty. Pareto dominance is descriptive; marginal intervals are not multiplicity-adjusted and are not causal evidence. The bundled contract is synthetic and is not company authority.
5. **D04 retains justified standard designs plus guarded sequential search.** The non-executing planner supports randomized full factorial, resolution-IV half fraction, basic Latin hypercube, and finite-grid greedy D-optimal designs. The seeded comparison found P4's D-optimal search matches exhaustive optimum and pyDOE3 on the fixed benchmark, while SciPy random-coordinate LHS improves centered discrepancy over basic LHS; the portable basic design remains and no optimization code is copied. Sequential expected-improvement proposals are offered only after independent-unit grouped holdout validation meets the engineer-specified error cap; multimodal benchmark cases fail closed. No D04 method launches experiments or claims a full-factorial power guarantee.
6. **D05 follows assignment and study design.** Randomized studies use assigned units for ITT, distinguish assigned from observed outcomes, report attrition and Welch-t intervals, and keep causal wording conditional. Three-period DiD checks the pretrend and includes sensitivity bounds and counterevidence. Unsupported, underpowered, malformed, or assumption-failing designs withhold point causal estimates rather than converting before/after association into causality.
7. **The MCP adapter is configurable but site-owned.** JSON-RPC stdio and Streamable HTTP are tested against a bundled realistic synthetic mock, with explicit tool/result maps and read-only/row/host bounds. No real tool identifiers, source semantics, joins, permissions, host, or credentials are supplied. Company configurations remain `PENDING_INTERNAL`; the site-side runner requires local approval references and an explicit configuration.
8. **P4 contributes a headless panel to the P1-owned workspace.** P4 ships no competing shell, route system, or design tokens. Its React/TypeScript panel consumes the shared source preview and evidence envelope, delegates charts to the host, and preserves the D02 grid and other claims in semantic tables. Eight component tests and strict type-checking pass against the local P1 package and schema snapshot; no P1 host commit was available. Formal WCAG, screen-reader, integrated-host, and target-OS review remain pending. The retired standalone page stays in local legacy evidence and is excluded from the transfer bundle.

## Qualification and OSS decisions

- Product runtime has no third-party Python packages. `qualification/benchmark-requirements.txt` pins NumPy, SciPy, scikit-learn, pyDOE3, scikit-optimize, and statsmodels for independent references and the D04 tournament. A clean environment on the recorded build host ran the full test suite with zero skipped tests. The entire resolved optional tree was scanned with pip-audit; this does not replace source review, OS/interpreter scanning, or a license/ownership decision.
- The previous scikit-learn 1.2.2 pin matched CVE-2024-5206; it was raised to 1.5.2 and the resulting current package advisory scan found no known vulnerabilities. See `release/DEPENDENCY_AUDIT.json` for full resolved versions and scanner scope.
- The fixed D04 benchmark compares SciPy `qmc.LatinHypercube` (basic/random-CD), pyDOE3 D-optimal against exhaustive enumeration, and scikit-optimize GP expected improvement using identical seeded functions and stated metrics. Keep results and limits in `release/D04_OSS_COMPARISON.json`; the runtime does not import these alternatives.
- No heavier causal, Gaussian-process, or multiobjective package was added to the product. The tested product capabilities and explicit refusal boundaries do not show a need for those dependencies in runtime. This does not claim that the bounded implementation replaces those packages for broader designs.
